# Prompts (Промпты)

> Промпты — это тоже код. Они версионируются, тестируются и улучшаются.
> Хранятся в `prompts/`, документируются здесь.

---

## Структура промпта

Каждый промпт состоит из:
- **System Prompt** — роль и контекст для LLM
- **Instructions** — пошаговые инструкции
- **Issue Types** — список факторов для поиска
- **Confidence Guidelines** — как оценивать уверенность
- **Output Format** — строгая JSON Schema

---

## Принципы промпт-инжиниринга

1. **Не «найди риски», а «классифицируй по списку».** LLM ищет соответствие заранее заданным типам, а не проявляет творчество.
2. **Жёсткая JSON Schema.** Ответ всегда одной структуры. Температура = 0.
3. **Confidence всегда числом.** От 0 до 1. Если формулировка двусмысленная — честно снижаем.
4. **Suggested rewrite обязательно.** Для каждого фактора — безопасная альтернатива или null, если её нет.
5. **Промпт не зависит от модели.** Можно использовать OpenAI, Claude, Ollama — поведение должно быть одинаковым.

## Как тестировать промпт

1. Взять реальный договор (обезличенный)
2. Прогнать через LLM с текущей версией промпта
3. Проверить:
   - Все ли очевидные факторы найдены?
   - Нет ли ложных срабатываний?
   - Confidence адекватен формулировкам?
   - Suggested rewrite применим на практике?
4. Записать результаты в Decision Journal
5. При необходимости — создать новую версию промпта

## Связь с Decision Catalogue

Промпт ищет факторы → Decision Catalogue содержит их веса и правила.
Изменение в промпте (новый фактор) требует изменения в каталоге, и наоборот.
